# 常见问题

[中文](FAQ.md) · [English](FAQ.en.md)

## “Codex 归档”和“冷存档”有什么区别？

Codex 归档只把会话移出常用视图，日志仍在 Codex 本地目录，通常不释放空间。冷存档会先校验内容和数据库快照，再把会话保存为可恢复包并移出 Codex 索引。只有目标目录在另一块磁盘时，才会释放 Codex 所在磁盘的空间。

## 恢复后还会出现在“设置 → 已归档的聊天”吗？

会。恢复会把原 JSONL 放回 `archived_sessions`，并把原数据库行恢复为 `archived=1`，所以它回到 Codex 的“已归档”状态，而不是普通活跃会话。2026-08-23 的 macOS 实测中，新版看板重扫后也将它识别为普通已归档。

## 聊天记录和日期会改变吗？

真实恢复实测中没有改变。恢复后的 JSONL 与冷存档前 SHA-256 完全一致；Session ID、标题、`created_at`、`updated_at`、`archived_at` 及对应毫秒字段保持原值。恢复发生的时间只写进独立审计记录，不会冒充会话更新时间。

## 为什么恢复按钮有时是灰色？

恢复会同时写回文件和数据库，必须证明 Codex 已完全退出。本机只有完成一次真实“运行中启动助手 → 完全退出 → 恢复成功”闭环后才启用按钮。手工创建标记文件不会通过验证。

## 为什么二次确认后计划还在？

确认只生成不可变执行单，不代表已经移动文件。v0.6.0 会在执行单存在时锁定原计划并隐藏重复入口；执行成功后自动清理已完成计划，只保留完成或失败凭证。若仍看到旧计划，先确认运行的是 v0.6.0 或更高版本，再刷新会话。

## “锁定此会话，不参与整理”是冷存档吗？

不是。锁定只让本工具不再推荐或执行整理，文件和 Codex 状态都不改变。冷存档才会迁移内容并建立恢复包。

## 为什么冷存档目录优先使用系统选择器？

系统选择器能减少路径拼写错误。高级手动输入仍然保留，但保存时会立即检查目录是否存在、可写，以及是否与用户目录或 Codex 数据目录危险重叠。

## 冷存档一定能释放空间吗？

不一定。同一磁盘内移动只能整理目录；只有迁移到另一块磁盘，例如外置硬盘，才会释放原磁盘空间。确认单会明确显示这一点。

## 会上传聊天数据吗？

不会。扫描、摘要、计划、哈希、恢复和审计均在本机完成；看板只绑定 `127.0.0.1`。请勿把数据库、JSONL、冷存档包、启动令牌或真实报告上传到 Issue。

## 支持哪些系统？

macOS 是完整执行链路的实测平台。Linux 在 CI 中验证扫描、看板、报告、测试和打包；原生目录选择和关闭桌面应用的行为可能不同。Windows 尚未验证。

## 我可以直接对唯一一份重要会话做永久删除吗？

不建议。先保留独立备份，再使用冷存档或 14 天隔离验证恢复。永久删除不可恢复，且真实机器上的完整永久删除流程仍标记为待实测。
