# 本地看板 UI 设计规范

本规范由数据密集型工具设计原则、本项目安全边界和真实大规模会话数据共同确定。

## 主流程

```text
首页看懂 → 会话选择 → 执行确认
```

- 服务启动时已经完成只读扫描，首页直接显示当前结果，不重复设置扫描门槛或模拟进度。
- 首页用生命周期、建议、空间和归档年龄图表回答“现在是什么情况”。
- 导航只保留首页、会话、执行计划和设置。
- 页面默认中文，右上角提供 English 切换；两种语言共用同一数据、动作和安全逻辑，禁止复制第二套页面。
- 短对话语义复核、具体批量候选和技术详情使用渐进披露。
- 正文关键词搜索必须由用户主动点击触发，命中结果显示会话级计数和受限上下文片段；不得预先扫描或把全部聊天正文放入 DOM。
- 推荐方案首批展示 25 条，全部会话首批展示 50 条，避免长标题导致过大的 DOM。

## 视觉系统

- 类型：本地生产力工具、数据密集型安全看板。
- 风格：极简档案凭证；以纸张、套印线、表格和印章表达本地留痕，不使用营销式大面积装饰。
- 强调色：登记蓝用于导航和主动作，朱红用于凭证章与危险动作；绿色和黄色继续只表达安全语义。
- 字体：使用本机宋体/楷体与衬线数字字体回退，不引入外部 CDN 或在线字体。
- 形态：卡片和控件以直角、细线与点线分隔为主，便笺阴影只用于执行阻塞。
- 纹理：纸张与登记网格必须由 CSS 生成，不把视觉稿或纹理图片作为页面背景。
- 间距：4/8 像素节奏。
- 动效：150–300ms，只使用透明度和位移；尊重 `prefers-reduced-motion`。

## 可访问性

- 正文与背景对比度至少 4.5:1。
- 交互目标至少 42px，窄屏主导航至少 44px。
- 提供跳到主要内容链接和明显的 `:focus-visible`。
- 刷新、搜索和详情加载使用明确的实时状态文本。
- 详情使用对话框语义、遮罩、Escape 关闭和焦点返回。
- 颜色之外必须保留文字状态，不用红绿颜色单独表达结果。

## 响应式

- 断点重点验证：375px、760px、1180px 和默认桌面宽度。
- 窄屏导航改为网格，不依赖整页横向滚动。
- 数据表只允许自身横向滚动，不扩大页面宽度。
- 卡片和指标在窄屏逐级降为两列、单列。
- 数据表允许自身横向浏览；主页图表和主导航不得产生横向溢出。

## 禁止

- 不使用外部 CDN、远程图标或在线字体。
- 不用 Emoji 充当导航和操作图标。
- 不一次渲染全部数百条候选。
- 不把 `planned_action` 画成已经完成的真实生命周期状态。
- 不让推荐方案或语义复核直接执行文件操作。
- 不用隐藏按钮代替解释阻塞原因。
