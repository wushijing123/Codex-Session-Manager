# 本地看板 UI 设计规范

本规范由 `ui-ux-pro-max` 的数据密集型工具建议、本项目安全边界和真实 535 条会话数据共同确定。

## 主流程

```text
首页看懂 → 会话选择 → 执行确认
```

- 服务启动时已经完成只读扫描，首页直接显示当前结果，不重复设置扫描门槛或模拟进度。
- 首页用生命周期、建议、空间和归档年龄图表回答“现在是什么情况”。
- 导航只保留首页、会话、执行计划和设置。
- 短对话语义复核、具体批量候选和技术详情使用渐进披露。
- 正文关键词搜索必须由用户主动点击触发，命中结果显示会话级计数和受限上下文片段；不得预先扫描或把全部聊天正文放入 DOM。
- 推荐方案首批展示 25 条，全部会话首批展示 50 条，避免长标题导致过大的 DOM。

## 视觉系统

- 类型：本地生产力工具、数据密集型安全看板。
- 风格：克制、清晰、偏高密度，不使用营销式大面积装饰。
- 强调色：单一蓝色；绿色、黄色和红色只表达安全语义。
- 字体：系统字体，不引入外部 CDN 或在线字体。
- 间距：4/8 像素节奏。
- 圆角：小控件 8–10px，卡片 12px，扫描首屏 24px。
- 动效：150–300ms，只使用透明度和位移；尊重 `prefers-reduced-motion`。

## 可访问性

- 正文与背景对比度至少 4.5:1。
- 交互目标至少 42px，窄屏主导航至少 44px。
- 提供跳到主要内容链接和明显的 `:focus-visible`。
- 扫描使用语义化 `progressbar` 和实时状态文本。
- 详情使用对话框语义、遮罩、Escape 关闭和焦点返回。
- 颜色之外必须保留文字状态，不用红绿颜色单独表达结果。

## 响应式

- 断点重点验证：375px、760px、1180px 和默认桌面宽度。
- 窄屏导航改为网格，不依赖整页横向滚动。
- 数据表只允许自身横向滚动，不扩大页面宽度。
- 卡片和指标在窄屏逐级从五列降为两列、单列。
- 数据表允许自身横向浏览；主页图表和主导航不得产生横向溢出。

## 禁止

- 不使用外部 CDN、远程图标或在线字体。
- 不用 Emoji 充当导航和操作图标。
- 不一次渲染全部数百条候选。
- 不把 `planned_action` 画成已经完成的真实生命周期状态。
- 不让推荐方案或语义复核直接执行文件操作。
- 不用隐藏按钮代替解释阻塞原因。
